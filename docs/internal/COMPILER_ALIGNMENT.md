# Compiler alignment: declarations and lexer

The author-defined language is the implementation contract. This stage implements typed and inferred variables, typed and inferred constants (`const auto` included), typed and inferred `for` declarations, standard comments, and file pragmas. Mutable variables retain their inferred type; constants reject writes. Dictionary iteration checks the key type, and array iteration checks the element type.

The lexer no longer has `let` or `mut` keywords. Their declaration forms, name-first constant declarations, colon binding annotations, if-let, and tuple binding syntax are rejected. The AST, binder, type checker, code generator, editor, snippets, and quick fixes were migrated together. Quick fixes resolve the actual declaration, including shadowed bindings.

Conventional unary precedence is tested through VM execution. CL++ has only its own VM target; the former Luau emitter and backend API were removed.

Validation on 2026-10-10:

- 190 unit cases, 1,156 assertions passed.
- 238 CTest checks passed, including unit cases, examples, stress harnesses, documentation fixtures, LSP, and the VS Code extension.
- 42 published executable documentation examples passed after promoting supported examples. 158 target specification blocks remain excluded from executable tests.
- Standard-library embedded source and historical executable fixtures were migrated without dropping tests.

This stage does not complete the language alignment. `def`, field defaults and named initialization, typed named functions, callback values, scoped enums, match syntax, optional narrowing, and shared data identity still require implementation and verification. See `docs/reference/status.md`; do not remove pending notices from unimplemented examples.
